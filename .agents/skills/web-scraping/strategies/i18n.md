# Scraping Internationalized (i18n) Sites

When dealing with non-English or multi-lingual websites, you must handle character encodings and locale preferences properly.

## 1. Character Encodings (UTF-8)
If you don't enforce encodings, you will see garbled text (e.g., `lÃ´i` instead of `lỗi`).
- **Charset Detection**: Check the `<meta charset="UTF-8">` tag or the `Content-Type: text/html; charset=utf-8` HTTP header.
- **BOM (Byte Order Mark)**: Some Windows files start with a BOM. Use robust parsers that strip it.
- **Enforce UTF-8**: Always ensure your HTTP clients request UTF-8, and always output JSON/CSV in UTF-8 format.

## 2. Locale and Language Headers
Many sites serve different content based on headers or query parameters.
- **Accept-Language**: Send `Accept-Language: vi-VN,en-US;q=0.9` to force the server to return localized content.
- **URL Parameters**: Watch for `?lang=en` or `?locale=fr` in API calls.

## 3. Selector Pitfalls
- **Avoid text-based selectors**: Never use `:contains("Buy Now")` because the site might translate it to "Mua ngay". Use stable IDs or class names instead.
- **CJK / RTL**: When dealing with Chinese/Japanese/Korean (CJK) or Right-To-Left (RTL) text, be aware that Unicode whitespace might be different, and string lengths in JavaScript are based on UTF-16 code units, not visual characters.

## 4. Internationalization Strategies
Always treat scraped text as raw unicode and avoid destructive `.replace()` regexes that strip non-Latin characters.
